MISSION
Build "Tilawa Coach", my personal recitation tutor: a mobile-first PWA that works offline. It takes me step by step through:
1. reading the Quran, from possibly zero;
2. full tajweed (Hafs 'an 'Asim via ash-Shatibiyyah);
3. reciting beautifully, with maqamat;
4. latmiya in the style of Mulla Basim al-Karbalai;

My Quran reference voice is Sheikh Muhammad Siddiq al-Minshawi: his murattal, mujawwad and with-children recordings (sources in B5).

The two core features:
(1) a TAJWEED MISTAKE CHECKER that listens to me and tells me exactly what I got wrong;
(2) a CALL-AND-RESPONSE ENGINE: the reciter calls and I answer, or I lead and a simulated crowd answers.

App:
- Vite + TypeScript (strict) + Preact (or Svelte);
- vite-plugin-pwa;

- Structure (final version recorded in ARCHITECTURE.md):

  - tests.

Audio:
- Web Audio + AudioWorklet, with all DSP off the main thread (worklets/workers, WASM if needed).
- MediaRecorder: iOS records audio/mp4, so decode it to PCM. Resample to 16 kHz mono (OfflineAudioContext) for models.
- getUserMedia with echoCancellation / noiseSuppression / autoGainControl OFF for analysis (advise headphones). ON is a fallback.
- iOS:
  - resume the AudioContext on a user gesture;
  - feature-detect navigator.audioSession and, if present, set "play-and-record" while recording and "playback" otherwise;
  - no vibration API exists, so never rely on haptics.
- Bluetooth (e.g. AirPods):
  - big latency;
  - recording may switch to the low-quality headset mic;
  - so detect it where possible, warn me, recommend wired headphones, and calibrate latency per output device.
- Input checks: clipping, too quiet, and noise floor (measured before each check).
- Pitch tracking: pitchy (McLeod) or YIN, inside the worklet.
- Playback:
  - slowed playback that keeps the pitch (preservesPitch);
  - A–B loop;
  - transpose a reference into my key (a SoundTouch-based shifter if its licence allows).

ML in the browser:
- onnxruntime-web or transformers.js, WebGPU first with a WASM fallback.
- GitHub Pages can't send the COOP/COEP headers needed for cross-origin isolation, so there's no SharedArrayBuffer and WASM runs SINGLE-THREADED. Measure that speed and prefer WebGPU. Don't add a COOP/COEP service-worker workaround unless tests prove that YouTube embeds, cross-origin audio and the PWA's own service worker still work.
- Lazy-load models only when the checker opens.
- Show the size, suggest Wi-Fi, show progress, cache in Cache Storage.
- Fetch model files with plain GET requests (no custom headers, no Range) so redirected Hugging Face hosts don't fail CORS preflight. Or self-host chunked copies (B5).
- The app is fully usable without models.

Storage safety:
- navigator.storage.persist().
- Safari may clear data for sites that aren't added to the Home Screen, so prompt "Add to Home Screen".
- One-file Backup/Restore through the share sheet (progress, settings, style profiles, optionally recordings), plus a weekly reminder.
- Offline packs per surah/juz, with size estimates and a storage manager. They use the EveryAyah audio if it sends CORS headers (offline audio needs them, B5); Quran Foundation audio isn't kept offline beyond 7 days (B5).

Arabic rendering:
- A self-hosted open-licence Quran font (e.g. Amiri Quran, OFL), or KFGQPC Hafs if its licence allows.
- Large default size with a slider; correct RTL.
- Tajweed colouring must not break letter joining. Test it in Chromium and WebKit; if spans break the shaping, use another technique and document it.
- Show a colour legend. Offer a colour-blind-safe mode: colour + underline style, or labels on tap.
- Optional Indo-Pak view, if authentic text is available.

Other:
- Daily reminder: there's no server, and web push needs one to send the message. Instead, an "Add a daily reminder to my calendar" button downloads a repeating .ics event at a time I choose, with the app's link.
- Budget: initial load under 3 MB, excluding models and audio packs. Split Quran data (text, timings, annotations) per surah and lazy-load it.
- Must pass: PWA installability (valid manifest + service worker; note that Lighthouse no longer has a PWA category, so check installability directly), plus Lighthouse accessibility and performance on a mobile profile.
